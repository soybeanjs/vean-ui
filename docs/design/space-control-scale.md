# 维度刻度：spacing 与 radius

> 定位：`@vean/theme` 字面量层里两条**刻度族**的当前契约——取值、单位、与 UnoCSS 的关系、消费面——以及一条判断准则：**哪些维度不该成为刻度族**（控件高度 / 图标 / 字号 / 阴影动效）。
> 状态：✅ 与代码同步。真相源是 [`packages/theme/src/literals.ts`](../../packages/theme/src/literals.ts) 与 [`packages/unocss/src/theme.ts`](../../packages/unocss/src/theme.ts)；实测数据的口径与复现方式见 §4。
> 相关：[theme.md](./theme.md) §3.11（字面量全表）· §5.1（UnoCSS theme key 归属）· §5.3（三处不回主题的刻度）

---

## 0. 速览

| 刻度族      | 形态                     | 档位                          | 发射的变量                    | 与 UnoCSS 的关系                                                                          |
| :---------- | :----------------------- | :---------------------------- | :---------------------------- | :---------------------------------------------------------------------------------------- |
| **spacing** | 一个网格单位 + 18 个系数 | `6xs` … `9xl`（2 – 128px）    | 只有 `--spacing-unit`（旋钮） | 接管 `theme.spacing` 的具名档与数字系数；同名档**同名同值**                               |
| **radius**  | 种子 + 7 个正系数倍      | `2xs` … `2xl` + `none`/`full` | `--radius` + 8 条             | 接管 `theme.borderRadius` 的 `2xs`…`2xl` / `none` / `full` / `DEFAULT`；`3xl` 留给 UnoCSS |

**不是刻度族**（§3）：控件高度、图标尺寸、字号与行高、阴影与动效。

判断准则一句话：**如果一个值总是另一个刻度的"某一列"或"某一档的伴生"，它就不是独立刻度。** 控件高度是 size 向量的高度列，图标尺寸是同一行的图标列，字号是这一行的文字列——给其中任何一列单独一个旋钮，都会和同行其它列失配。

**两条刻度都只有一个旋钮**：`spacing` 动 `--spacing-unit`，`radius` 动 `--radius`。其余档位都是系数或倍数，随旋钮在运行时一起移动（`calc()` 推导，不是构建期算好的字面值）。

## 1. spacing：一个网格单位 + 18 个系数

### 1.1 取值

`SPACING_GRID_COEFFICIENTS`（[literals.ts](../../packages/theme/src/literals.ts)）是唯一真相源；下表是它在**默认单位**（`--spacing-unit: 0.25rem`，根字号 16px）下的取值：

| 档位  | 系数 | 默认值 | 来源                                             |
| :---- | ---: | -----: | :----------------------------------------------- |
| `6xs` |  0.5 |    2px | **扩充**（上游起点以下）                         |
| `5xs` |    1 |    4px | **扩充**                                         |
| `4xs` |  1.5 |    6px | **扩充**                                         |
| `3xs` |    2 |    8px | **扩充**                                         |
| `2xs` |  2.5 |   10px | **扩充**                                         |
| `xs`  |    3 |   12px | UnoCSS                                           |
| `sm`  |  3.5 |   14px | UnoCSS                                           |
| `md`  |    4 |   16px | **扩充**（= UnoCSS `DEFAULT`，补上缺失的中段名） |
| `lg`  |  4.5 |   18px | UnoCSS                                           |
| `xl`  |    5 |   20px | UnoCSS                                           |
| `2xl` |    6 |   24px | UnoCSS                                           |
| `3xl` |  7.5 |   30px | UnoCSS                                           |
| `4xl` |    9 |   36px | UnoCSS                                           |
| `5xl` |   12 |   48px | UnoCSS                                           |
| `6xl` |   15 |   60px | UnoCSS                                           |
| `7xl` |   18 |   72px | UnoCSS                                           |
| `8xl` |   24 |   96px | UnoCSS                                           |
| `9xl` |   32 |  128px | UnoCSS                                           |

`6xs` … `xl` 相接后是一条**连续的 2px 网格 2 – 20px**，正好覆盖组件实测的全部小间距；`2xl` 起切到 UnoCSS 的粗网格（布局域），原值保留。

工具类名就是档位名：`gap-md` / `p-2xl` / `mt-3xs`。

### 1.2 为什么是"一个单位 + 系数"而不是 18 条变量

发射 18 个 `--spacing-*` 变量意味着每个主题块多 18 条声明，而它们的读者只有适配器一个——适配器可以就地算 `calc(var(--spacing-unit) * k)`。因此：

- **变量只有旋钮一个**：`--spacing-unit` 是 `spacing` 选项（预设 `compact` 0.75 / `default` 1 / `relaxed` 1.25 / `spacious` 1.5，或任意倍率）的唯一落点；
- **系数与类名里的数字是同一个数**：`p-4` ⇔ 系数 4，`gap-md` ⇔ 系数 4，所以具名档与数字类必然同源同值，不会各自漂移；
- **只动间距**：字号、控件高度、圆角、图标尺寸都不读 `--spacing-unit`（§3），所以这个旋钮是干净的"紧凑 / 宽松"开关。`size`（根字号）与它正交——最终间距 = 单位 × 根字号，两个旋钮会叠加。

`spacing-unit` 刻意排除在刻度之外（`SPACING_RUNGS` 不含它），否则它会被映射成 `spacing-unit` 工具类、系数换算读到非数值。

### 1.3 与 UnoCSS 同名同值

UnoCSS（preset-mini）的 `theme.spacing` 具名档是 `xs` 0.75rem … `9xl` 8rem（12 档，另加 `DEFAULT` 1rem、`none` 0`）。这 12 档我们**一律同名同值保留，不覆盖上游语义**；与上游的差异只有 6 个新增：向下扩 `6xs`…`2xs`，中间补 `md`（= `DEFAULT`）。

`packages/unocss/test/theme.spec.ts` 有逐档比对上游的断言（读 preset-mini 的 `theme.spacing`），因此上游改档会立刻失败，而不是静默分叉。

对我们的刻度来说，这条对齐的代价与收益都很明确：代价是失去 28/32/40px 三个精确档位（§4.3 的候选 D 曾占有它们），收益是尾部平均偏差反而更低（1.04px vs 1.30px）且**与生态同名档同值**——消费者从 UnoCSS 文档里读到的 `gap-xl` 含义，在这里依然成立。

### 1.4 数字工具类同源：1025 个数字键

preset-mini 的取值链是 **`theme.spacing[key] ?? n × 0.25rem`**（`directionSize` / `handleGap` / `handleInsetValue` / `handleTranslate`）——"数字间距不读 theme"只在**没有该键**时成立。适配器因此登记 `0` … `64`、**步长 `0.0625`（网格单位的 1/4）**共 **1025 个数字键**，值同为 `calc(var(--spacing-unit) * k)`：

```
p-4      → padding: calc(var(--spacing-unit) * 4)
px-2.5   → padding-left: calc(var(--spacing-unit) * 2.5)
p-0.625  → padding: calc(var(--spacing-unit) * 0.625)
my-0.4375→ margin-top: calc(var(--spacing-unit) * 0.4375)
gap-md   → gap: calc(var(--spacing-unit) * 4)     /* 与 p-4 同值 */
-mt-4    → margin-top: calc(calc(var(--spacing-unit) * 4) * -1)
p-5xs    → padding: var(--spacing-unit)           /* 系数 1 发射裸引用 */
```

**枚举步长不是网格单位**：系数 1 是 `0.25rem`（单位），但"哪些数字有键"必须比单位更细。只走单位的多重数（旧行为：`0.25` / `0.5` / `0.75` / `1` / `1.25`…，共 257 键）会把 1/8、1/16 档漏给 preset-mini 的硬编码除法——`p-0.625` 产出 `0.15625rem`（= 0.625 × 0.25rem）而隔壁 `p-0.75` 是 `calc(var(--spacing-unit) * 0.75)`。默认单位下两者数值相同，所以肉眼无差；一旦消费者拖动 `spacing`，被漏掉的那些**冻结**、其余缩放。按 `packages/ui/src`（样式 + 组件模板）全量抓取，这类用法共 **77 处 / 26 个类值**（间距族 75 处：`p-0.875` 15、`py-0.875` 11、`p-0.625` 6、`gap-0.875` 5…；偏移族 2 处：`top-1.875` / `end-1.875`）。`page-tabs` 的 `close` 梯度是典型样本：`p-0.625` / `p-0.75` / `p-0.875` / `p-1` / `p-1.125` / `p-1.25` 里只有三个跟随旋钮。未使用的键不产 CSS，所以加密步长只增加查表项（1025 键 ≈ 47KB 配置对象，构建期一次），不增加产物。步长是**固定格点**而非兜底：格点之外的系数（`p-0.3`）仍回落 UnoCSS 原生——组件作者写间距时落在 1/16 网格上即可（库内现有取值全部落在其上）。

这一步是"只调间距"能否成立的前提：库里 **1,594 处**间距用法**全部是数字类**（具名档 0 处，§4.2），不登记数字键，旋钮就只会动那 0 处。

**不动的是**：`w-*` / `h-*` / `size-*` 读 `theme.width` / `theme.height`，不经过 `theme.spacing`——实测 `h-8` 恒为 `2rem`、`size-4` 恒为 `1rem`。**同样不动的**：任意值 `p-[7px]` 与分数 `p-1/2` 保留原义（逃生舱）；超出登记区间（`p-80` 以上）回落 UnoCSS 原生、不缩放。

**已知副作用**：`inset-*` / `top-*` / `translate-*` / `basis-*` 与间距共用 `theme.spacing`，会一起缩放（库内 inset 307 处，`inset-0` 不受影响）。这是**接受**的：它们是同一节奏的偏移（如 alert 关闭按钮 `top-1.25 end-1.25` 跟着 padding 一起变大，视觉关系反而更稳）。若要隔离，唯一干净做法是加一条 `order: -1` 的自有 inset 规则、复用 `@unocss/preset-mini/utils` 的 `h` 与 `insetMap` 重发一遍。

### 1.5 消费面

| 面                | 写法                                                                                                                                               | 说明                                                                       |
| :---------------- | :------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------- |
| 库内 recipe       | 数字类：`h-8 px-2.5 gap-2 text-sm`                                                                                                                 | 具名档 0 处。数字类读同一个单位，所以旋钮照样作用到它们身上                |
| 主题定制面板      | 具名档：[`preview-spacing.vue`](../../apps/docs/src/components/theme-editor/preview-spacing.vue) 逐档渲染 `p-2xs` … `p-2xl` + `gap-3xs` … `gap-xl` | 面板需要的是"整条刻度可见"；滑块改的是 `spacing` 选项，不是某档的值        |
| 消费者 / 组件作者 | 任选：`gap-md` ≡ `gap-4`（同值同源）                                                                                                               | 写具名档可读性更好，写数字类与 UnoCSS 文档一致；两条路都不会绕过 `spacing` |

### 1.6 每 size 控件向量就是这条刻度上的一段窗口

[`_field.ts`](../../packages/ui/src/styles/_field.ts) 的 `fieldSize` 是表单控件的共有向量，它的 padding-x 与 gap **各自都是 spacing 刻度上连续相邻的 6 档**（高度列见 §3.1）：

| size  | 高度        | padding-x              | gap                     | 文本        |
| :---- | :---------- | :--------------------- | :---------------------- | :---------- |
| `xs`  | `h-6` 24px  | `px-1.5` 6px（`4xs`）  | `gap-1` 4px（`5xs`）    | `text-2xs`  |
| `sm`  | `h-7` 28px  | `px-2` 8px（`3xs`）    | `gap-1.5` 6px（`4xs`）  | `text-xs`   |
| `md`  | `h-8` 32px  | `px-2.5` 10px（`2xs`） | `gap-2` 8px（`3xs`）    | `text-sm`   |
| `lg`  | `h-9` 36px  | `px-3` 12px（`xs`）    | `gap-2.5` 10px（`2xs`） | `text-base` |
| `xl`  | `h-10` 40px | `px-3.5` 14px（`sm`）  | `gap-3` 12px（`xs`）    | `text-lg`   |
| `2xl` | `h-12` 48px | `px-4` 16px（`md`）    | `gap-3.5` 14px（`sm`）  | `text-xl`   |

同阶梯在 `fieldMinSize` / `fieldWrap` / `fieldMultiple` 复刻了三次（值等价，分别是 `min-h-*` / 换行 `py-*` / `data-[multiple]` 变体），另有三处独立实现：`button.ts`（高度与 `fieldSize` 一致，padding 曲线自己更快）、`toolbar.ts`（外层 24–56px，内嵌按钮比外层低一档）、`checkbox.ts`（图标 `size-3`…`size-6` + gap 6/7/8/10/12/14）。

**这正是"不需要给 padding / gap 造 token 族"的证据**：每 size 的"用哪一档"是 recipe 层的策略表（一处维护，其它组件照抄），而不是刻度本身。

## 2. radius：种子 + 正系数倍

### 2.1 取值

| 档位            | 与种子的关系                 | 默认种子 0.5rem 下 |
| :-------------- | :--------------------------- | -----------------: |
| `--radius`      | 种子（`ThemeRadiusValue`）   |                8px |
| `--radius-2xs`  | `calc(var(--radius) * 0.25)` |                2px |
| `--radius-xs`   | `calc(var(--radius) * 0.5)`  |                4px |
| `--radius-sm`   | `calc(var(--radius) * 0.75)` |                6px |
| `--radius-md`   | `var(--radius)`              |                8px |
| `--radius-lg`   | `calc(var(--radius) * 1.25)` |               10px |
| `--radius-xl`   | `calc(var(--radius) * 1.5)`  |               12px |
| `--radius-2xl`  | `calc(var(--radius) * 1.75)` |               14px |
| `--radius-3xl`  | `calc(var(--radius) * 2)`    |               16px |
| `--radius-4xl`  | `calc(var(--radius) * 2.25)` |               18px |
| `--radius-none` | `0`                          |                  0 |
| `--radius-full` | `9999px`                     |             9999px |

`md` 是种子的**直接引用**（`var(--radius)`，不是系数倍）：刻度中央与种子同值，读数最直观。其余 8 档是 +0.25 步长的系数倍，于是默认种子下逐档落在 0.125rem 的整数倍上（2 / 4 / 6 / 8 / 10 / 12 / 14 / 16 / 18px）。

`none` / `full` 是刻度两端极值，由 `NON_RUNG_TOKENS` 排除在刻度外（不参与系数表与单调性断言）。

### 2.2 为什么是倍数制，而不是"种子 ± 固定偏移"

偏移制（`calc(var(--radius) - 2px)` 这类）有一个静默失败的缺陷：**偏移一旦大于种子，算出的就是负值**——负 `border-radius` 属非法 computed value，声明被丢弃，元素静默变直角（`rounded-2xs` 与 `rounded-none` 再无区别）。最小种子预设（`2xs` 0.125rem）小于曾经的最大偏移 0.5rem，所以定制面板的圆角滑块**左起档位是陷阱**：拖过去，内层圆角静默变直角。

改用正系数倍后：

- **任何**预设与任何原始种子（含 `1px` / `2px` 这类极小值）都得到正值、单调递增的刻度；
- **每档与种子成固定比例**，不随预设漂移（偏移制在预设间会从 50% 漂到 88%）；
- **默认种子下逐档落在 0.125rem 网格上**：2 / 4 / 6 / 8 / 10 / 12 / 14 / 16 / 18px；
- 代价：非默认预设下由"固定 2px 步长"变为"固定比例"，大种子的档位更分散；最小种子（`2xs` 0.125rem，即 2px）的最小档是 0.5px（亚像素但合法——比静默变直角诚实）。

守卫在 `packages/theme/test/engine-features.spec.ts`：`derives the radius scale as multiples of the seed` 与 `keeps every radius rung a positive multiple of the seed`（系数表、单调性、全部预设 + 极小种子逐档 > 0、默认种子落在 0.125rem 网格上）。

### 2.3 两个轴都成立：密度与预设

`--radius` 是**活的 CSS 变量**，不是构建期常量。因此两条轴都自动跟随：

| 轴   | 旋钮                                     | 表现                                                       |
| :--- | :--------------------------------------- | :--------------------------------------------------------- |
| 密度 | `size` → `html { font-size }`（12–24px） | 种子是 rem，整条刻度随之缩放；消费者只改 `--radius` 也生效 |
| 预设 | `radius` 选项（`2xs` … `4xl`，共 9 档）  | 改种子即整条刻度移动，不需要逐档覆写                       |

预设表（`THEME_RADIUS`）与刻度同名同序，九档以 `0.125rem` 为步长、`md` 居中，且 `THEME_RADIUS.md` 就是 `LITERAL_DEFAULTS.radius`——所以滑块拖到 `md` 与「不改」是同一个外观（有测试钉住这个等式）。

这也是"回 `calc()` 而不用字面值"的理由：字面值刻度在消费者自己样式表里覆盖 `--radius` 时不会跟随，`calc()` 会。代价是别名块略长。

### 2.4 `rounded-*` 的归属

| 工具类                                    | 来源     | 说明                                                               |
| :---------------------------------------- | :------- | :----------------------------------------------------------------- |
| `rounded-2xs` / `rounded-xs`              | **主题** | UnoCSS 无这两档                                                    |
| `rounded-sm` / `md` / `lg` / `xl` / `2xl` | **主题** | 接管；值与 UnoCSS 不同（UnoCSS 的 `md` 是 0.375rem）               |
| `rounded-3xl` / `rounded-4xl`             | **主题** | 接管；UnoCSS 的 `3xl` 是固定 1.5rem，不随种子移动                  |
| `rounded`（`DEFAULT`）                    | **主题** | 指向种子本身；UnoCSS 的 `DEFAULT` 是 0.25rem，比 `rounded-sm` 还小 |
| `rounded-none` / `rounded-full`           | **主题** | 值与 UnoCSS 一致，但归主题所有                                     |

整族由 `RADIUS_RUNG_KEYS` 派生（从 `LITERAL_DEFAULTS` 的 `radius-*` 减去两个极值），所以加一档只改一张表，映射自动跟随。`3xl` / `4xl` **刻意回主题**：上游这两档是固定长度，留在上游会让刻度在 `2xl` 处断链——同一族的深档不跟随种子，是比"与上游不同名同值"更坏的失败模式（docs 首页那处装饰方块用的是 `rounded-3xl`，默认种子下由 1.5rem 变 1rem）。

## 3. 什么不是刻度族

### 3.1 控件高度

**控件高度不是独立刻度，它是 size 向量的高度列。** 证据与理由：

1. **同一行还有别的列**：`fieldSize` 的一行是"高度 + padding-x + gap + 文本"（§1.6），四列一起随 `size` 移动。只给高度一个旋钮会与同行的字号/行高失配——字号 ×1.5 时 `text-sm` 的行高 30px 塞进固定 32px 的 `h-8`，只剩 1px 余量。
2. **数字 `h-*` 已经精确覆盖**：`h-5` … `h-14` 是 `n × 0.25rem`，实测 20–56px 区间 193 处里 **97.4%** 落在 4px 网格上（§4.4）。具名 `h-xl` 才是布局刻度（36rem），数字高度不是。
3. **"第二个名字"没有收益**：把 8 档提成 `--control-height-*`，每一档都等于数字高度刻度的一档（`2xs`→`h-5`、`xs`→`h-6`、`md`→`h-8`…），库内与用户文档站都是 0 消费。

因此：控件高度用数字 `h-*` / `min-h-*`，随 `size` 的根字号缩放（rem）。**不要**为它加 `h-control-*` 族；要调整某档高度，改的是 recipe 里那一行。

> `theme.height` / `theme.minHeight` 里没有任何 `control-*` 键，因此 `h-control-*` / `min-h-control-*` / `size-control-*` 不产出任何声明。

### 3.2 图标尺寸

`size-*` 读 `theme.height` / `theme.width`，**不经过 `theme.spacing`**（实测 `size-4` 恒为 `1rem`）。控件内图标是 6 档（12 / 14 / 16 / 18 / 20 / 24px），与 `fieldSize` 逐档同行，用原生 `size-3` … `size-6`；组件自有尺寸（avatar / swatch / spinner 的 28–64px）是组件轴，不进刻度。

未决：是否补一族 `size-icon-{size}`（§6）。

### 3.3 字号与行高

字号 / 行高是 UnoCSS 的 `fontSize` 档位，主题**只补不替换**：`xs` … `9xl` 保留 Wind3 自己的 size / line-height 配对，适配器只在它最小的 `xs` 之下补三档 `4xs` / `3xs` / `2xs`——也正是库里真正用到的三个（`text-2xs` / `text-3xs` / `text-4xs`）。

理由：主题化字号意味着"换主题会改组件里文字的大小"，那是排版决策而不是配色决策；而且字号一旦随主题移动，行高、控件高度、图标尺寸都得跟着联动才不出错（正是 §3.1 的失配问题）。

### 3.4 阴影与动效

同样归 UnoCSS：`shadow-sm|md|lg|xl` 与 `duration-200` / `ease-in-out`。没有 `--shadow-*` / `--duration-*` / `--ease-*` token——适配器从不映射 `boxShadow`，组件写的是数字时长，那批变量**没有任何读者**（既不进工具类，也没有组件引用）。保留下来的效果是：主题不可能悄悄改变组件的投影与动感。

## 4. 取值依据（实测）

### 4.1 口径与复现

- **样本**：`packages/ui/src/styles/*.ts`——83 个 `// @unocss-include` 的 style recipe 文件，是库内全部 utility 类名的来源；
- **换算**：数字间距 / 高度 = `n × 0.25rem`，默认根字号 16px（`p-4` = 1px × 16 = 16px 的 4 倍网格）；
- **覆盖率**：用量落在刻度点上的比例；离格项按**最近的档位**计偏差（均值、`>3px` 占比）；
- **复现**：口径即上三条——任何按此口径重跑一遍的扫描应得到同量级数字。样本随 recipe 改动而漂移，因此本文只承诺**结论**（哪条刻度更优、量级如何）稳定，不承诺小数位逐次一致。

### 4.2 spacing 分布与 18 档的覆盖率

| 族           |     用量 | 去重值 |  精确命中 |   离格均值 |   `>3px` | 最高频 8 个值（px）               |
| :----------- | -------: | -----: | --------: | ---------: | -------: | :-------------------------------- |
| gap          |      701 |     20 |     86.6% |     0.99px |     0.0% | 8 / 12 / 10 / 6 / 4 / 14 / 7 / 16 |
| padding-x    |      336 |     23 |     82.4% |     1.27px |     0.9% | 8 / 6 / 12 / 10 / 14 / 4 / 16 / 7 |
| padding-y    |      283 |     18 |     73.5% |     0.89px |     0.0% | 4 / 6 / 8 / 5 / 10 / 7 / 12 / 24  |
| padding 全写 |      231 |     19 |     62.3% |     0.89px |     0.0% | 4 / 6 / 7 / 12 / 8 / 10 / 5 / 3   |
| padding 单边 |       49 |     20 |     71.4% |     2.21px |     6.1% | 8 / 4 / 6 / 10 / 12 / 3 / 5 / 14  |
| space-*      |       18 |      6 |     33.3% |     0.88px |     0.0% | 3 / 3.5 / 4 / 5 / 6 / 7           |
| margin       |       19 |      — |         — |          — |        — | 全部是 `m-0`                      |
| **合计**     | **1594** |     32 | **80.1%** | **1.04px** | **0.4%** | —                                 |

（合计不含 margin——它只有 `m-0`。）

两点观察：

1. **偶数网格是主干**，但**奇数 / 半像素不是噪声**：3 / 5 / 7 / 9 / 11.5 / 15 / 21px 合计 242 处（15.2%），其中 5px（79 处）与 7px（100 处）是离格值里最大的两个。它们不是自由微调，而是"6 档塞进 24–48px 高度"的**手写补偿**——`gap-1.25` / `1.75` 正是这个约束的必然结果。而它们在系数表上**都算得出来**（1.25 / 1.75 都是 0.25 的整数倍），所以数字类路径能表达它们，只是不与某条 2px 网格重合。
2. **尾部确实存在**：24px（42 处）、28px（9）、32 / 40px（各 3）、以及 46 / 54 / 64 / 72 / 82px 各 1 处。刻度不能只到 20px——这也是把上游的 `2xl` … `9xl` 原样保留的原因。

### 4.3 候选刻度的对比（为什么是这 18 档）

同一份样本上比较五种候选：

| 候选                                          |   档数 |  精确命中 |   离格均值 |   `>3px` |
| :-------------------------------------------- | -----: | --------: | ---------: | -------: |
| **A｜现状：UnoCSS 同名 + `6xs`…`2xs` + `md`** | **18** | **80.1%** | **1.04px** | **0.4%** |
| B｜粗网格（4/8/12/16/24/32/48）               |      7 |     43.9% |     1.87px |     3.6% |
| C｜1px 细网格（1…24 全档 + 尾）               |     30 |     96.2% |     1.82px |     0.3% |
| D｜自有 13 档（2px 网格 2–20 + 24/28/32/40）  |     14 |     80.9% |     1.30px |     0.4% |
| E｜只用 UnoCSS 具名 12 档（12…128）           |     12 |     24.2% |     5.32px |    58.5% |

读法：

- **B 证明"减少档位"不可行**：真实用法在 6 / 10 / 14px 上密集分布，粗网格把它们全部推离 2px，覆盖掉到不足一半。
- **C 证明"1px 细网格"是另一条路**：精确率可到 96%，代价是 30 档、低端档距只有 1px，而且把上面那些"手写补偿"固化成刻度——违反"档位应表达角色差"的初衷。它的离格均值（1.82px）甚至比 A 更差：不在网格上的那些值被吸到了更远的位置。
- **D 是最接近的对照组**：它保留了我们自己的三个精确档位（28 / 32 / 40px），覆盖率与 A 基本持平（80.9% vs 80.1%），但**尾部偏差更大**（1.30px vs 1.04px）。
- **E 证明刻度不能只抄上游具名档**：上游具名档是排版节奏（从 12px 起），组件间距的主体在它之下，覆盖只有 24%。
- **A（采纳）**：与 D 换取了几乎同样的覆盖，但换来了"上游同名档不过期"和更低的尾部偏差。

### 4.4 控件高度分布：数字网格已经够用

20–56px 区间的 `h-*` / `min-h-*`（`< 20px` 是进度条 / 滑块轨道 / 徽标这类"粗细"，`> 56px` 是布局高度，都不计入）：

| px   |  20 |  22 |  24 |  28 |  32 |  36 |  40 |  44 |  48 |  56 |
| :--- | --: | --: | --: | --: | --: | --: | --: | --: | --: | --: |
| 次数 |  19 |   5 |  35 |  31 |  31 |  23 |  25 |   2 |  20 |   2 |

合计 193 处，**97.4% 落在 4px 网格上**；离格只有 22px（5 处）与 44px（2 处，input-otp）。`44px` 只有 2 处，不值得为它设档。

结论：数字 `h-*` 覆盖了这个区间，控件高度不需要 token 族（§3.1）。`22px` / `44px` 这类偶尔出现的值按需吸附到相邻数字档即可。

## 6. 未决问题

1. **细元素（8 / 10 / 12 / 14px）是否需要一族"粗细"刻度**：实测分布在进度条、滑块轨道、徽标、抽屉把手（`h-1`…`h-3.5`），语义是粗细 / 直径而不是高度。倾向**不设**，但若组件作者反复手写，可加 3–4 档。
2. **图标刻度是否与 spacing 共用**：`size-*` 不读 `spacing`（§3.2），若用 `size-lg` 这类写法会削弱语义（"lg 是谁的 lg"）；倾向保留独立的 `icon-*` 族，而不是复用 spacing 档位名。
3. **页面级语义别名**（如 `--spacing-gutter: var(--spacing-2xl)`）：当前页面节奏直接用 `2xl` / `3xl` 档。若出现"页面 gutter 需要被主题单独调配"的真实需求，再以别名形式加回。
4. **`8xl` / `9xl`（96 / 128px）仍归 UnoCSS**：若页面级布局刻度也需要主题化，另开议题（要覆盖上游值时，先在 `packages/unocss/test/theme.spec.ts` 的逐档对齐断言里说明理由）。`rounded-3xl` / `rounded-4xl` 已不属于此列——它们已回主题（§2.4）。
