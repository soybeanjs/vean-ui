# 升级指南：日期引擎切换为 `date-fns` + `Date`

v0.50.0 用 `date-fns` 与平台 `Intl` API 替换了 `@internationalized/date`（及 `@internationalized/number`）。公开值模型改为原生 `Date` 对象——不再提供 `CalendarDate`/`ZonedDateTime` 适配层。首个版本只支持**本地日期**；带时区的值不在范围内（后续视需求单独立项）。

## 1. 值模型映射

| v0.40.x                                              | v0.50.0                                                  |
| ---------------------------------------------------- | -------------------------------------------------------- |
| `CalendarDate`（日历日）                             | **本地 00:00** 的 `Date`                                 |
| `CalendarDateTime`（日期 + 时间）                    | `{ date: Date, time: Date }`（`DateTimeValue`）          |
| `Time`（一天中的时间）                               | 小时/分钟/秒部分有意义的 `Date`（`TimeValue`）           |
| `DateRange` `{ start?: DateValue, end?: DateValue }` | `{ start?: DateValue \| null, end?: DateValue \| null }` |
| `TimeRange` `{ start?: TimeValue, end?: TimeValue }` | `{ start?: Date \| null, end?: Date \| null }`           |
| `DateMatcher` / `TimeMatcher`                        | `(date: Date) => boolean` / `(time: Date) => boolean`    |

导出的类型名（`DateValue`、`DateRange`、`TimeValue`、`TimeRange`……）保持不变——只是形状变了。原生 `Date` 始终是合法的 `DateValue`；一旦带时间部分，就需要 `{ date, time? }` 对象。时间值会被归一化到固定本地纪元（2000-01-01），只有时分秒有意义。

```diff
- import { CalendarDate, CalendarDateTime, Time } from '@internationalized/date';
- const day = new CalendarDate(2026, 4, 19);
- const dateTime = new CalendarDateTime(2026, 4, 19, 14, 30);
- const time = new Time(9, 30);
+ import { createDate, createTime } from '@vean/aria/date';
+ const day = createDate(2026, 4, 19);                       // 本地零点，月份 1 起始
+ const dateTime = { date: createDate(2026, 4, 19), time: createTime(14, 30) };
+ const time = createTime(9, 30);
```

也可以不用助手：`new Date(2026, 3, 19)`（原生构造函数的月份是 0 起始，注意区分）。

## 2. 字段值形状

- `SDateField` / `SDatePicker`：日粒度为 `Date`；使用时间粒度后为 `{ date, time? }`。
- `STimeField`：`Date`（仅时间部分）。
- `SCalendarRange` / `SDateRangeField` / `SDateRangePicker`：`{ start, end }`，空边界为 `null`。
- `STimeRangeField`：`{ start, end }`，元素为时间 `Date`。

```diff
- const range = { start: new CalendarDate(2026, 4, 18), end: undefined };
+ const range = { start: createDate(2026, 4, 18), end: null };
```

## 3. 日历运算与比较

`@internationalized/date` 的实例方法不复存在。请改用 `date-fns` 函数、`@vean/aria/date` 的内核助手或原生 `Date` 访问器：

| v0.40.x                               | v0.50.0                                                                  |
| ------------------------------------- | ------------------------------------------------------------------------ |
| `date.add({ days: 1 })`               | `addDays(date, 1)`（date-fns）                                           |
| `date.subtract({ months: 1 })`        | `addMonths(date, -1)`                                                    |
| `date.set({ day: 1, month: 2 })`      | `setSegmentParts(date, { day: 1, month: 2 })`（月份 1 起始，日期夹取）   |
| `date.cycle('day', 1)`                | `cycleSegment(date, 'day', 1)`                                           |
| `date.copy()`                         | `cloneDateValue(value)` / `new Date(date.getTime())`                     |
| `date.toString()`（ISO `yyyy-MM-dd`） | `toISODateString(date)`                                                  |
| `date.compare(other)`                 | `toDate(a).getTime() - toDate(b).getTime()` 或 `isBefore`/`isAfter` 助手 |
| `isSameDay(a, b)` 等                  | 同名，现从 `@vean/aria/date` 导出                                        |
| `.day` / `.month` / `.year`           | `date.getDate()` / `date.getMonth() + 1` / `date.getFullYear()`          |

注意夹取语义：`setSegmentParts` 会把日期夹取到目标月份的天数内（1 月 31 日 + `month: 2` → 2 月 28 日），与之前行为一致；而 `addDays`/`addMonths` 与 `date-fns` 一贯行为相同，会自然溢出到下个月。

## 4. 格式化与解析

- `@internationalized/date` 的 `DateFormatter` → 原生 `Intl.DateTimeFormat`。`useDateFormatter(initialLocale, opts)` 组合式保持相同的方法面（`custom`、`part`、`toParts`、`fullMonth`……），但所有方法都接收 `Date`。
- `parseDate('2026-04-18')` → `parseISO('2026-04-18')`（date-fns）或 `createDate(2026, 4, 18)`。
- `parseDateTime(...)` / `parseZonedDateTime(...)` → `parseISO` / `new Date(...)`。首个版本不支持带时区前缀的字符串。
- `@internationalized/number` 的 `NumberFormatter` / `NumberParser` → `@vean/aria/shared` 的 `createNumberFormatter(locale, options)` / `createNumberParser(locale, options)`，两者都是 `Intl.NumberFormat` 的薄包装（`parse` + `isValidPartialNumber` 契约不变）。

## 5. 时区

`ZonedDateTime`、`CalendarIdentifier`、非公历日历、`toDate(value, timeZone)` 转换以及 `timeZoneName` 分段均已移除。`hideTimeZone` 作为一个版本周期的空操作 prop 保留。如果当前就需要时区感知的选择器，请在应用边界自行转换（例如保存 UTC `Date`、展示时做偏移）——原生的时区方案可能后续单独立项。

## 6. 检查清单

date-fns 在本库内通过**子路径模块**导入（`date-fns/addDays`、`date-fns/isSameDay`……）而非桶导出，让不具备 `sideEffects` 感知摇树能力的环境（webpack 4、CJS SSR、Jest）也只加载实际用到的函数。建议你自己的代码遵循同样风格：

```bash
# 旧依赖应已移除
pnpm remove @internationalized/date @internationalized/number
pnpm add date-fns
```

```bash
# 不应再有运行时引用
grep -rn "@internationalized" src/
# 期望：无输出
```
