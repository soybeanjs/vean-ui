# DOCS SITE — @vean/docs

## AI ASSISTANT BRIDGE

For any AI assistant editing files under `apps/docs/`:

1. Load the component development skill at `.agents/skills/vean-ui-develop/` — [surfaces.md](../../.agents/skills/vean-ui-develop/surfaces.md) (Playground + Docs sections) owns the delivery rules for this app.
2. For `**/*.{ts,tsx,js,jsx}` edits, load the global `typescript-functional-style` skill; for `**/*.vue`, also `vue-sfc-structure`.

**App:** `apps/docs/` → private workspace `@vean/docs`. Not published.
**Role:** the **user-facing** documentation site. Distinct from the repo's `docs/` directory, which is the maintainer docs hub — [docs/README.md](../../docs/README.md) states this split explicitly. Do not move maintainer docs into this app or vice versa.

## STACK QUIRKS

- **SSG on ubean, NOT VitePress.** `ubean.config.ts` sets `mode: 'ssg'`. Content is Markdown under `src/content/{en,zh}/`, routing is file-based, i18n is built in with `strategy: 'prefix_except_default'` (default `en`, so zh lives under `/zh`).
- **`colorMode: false` deliberately.** `@vean/theme`'s `createThemeInitScript` owns first-paint theme application (see `src/app.ts`). Leaving the built-in color mode on would create a second, conflicting source of truth.
- **Path aliases resolve to source, not dist**: `~` → `apps/docs/src`, `@` → `packages/ui/src`. So UI edits appear in `pnpm dev:docs` with no rebuild — and conversely, a UI type error surfaces here before the library's own build does.
- **Dynamic routes are not prerendered by `prerender.all`.** `build/docs-routes.ts` enumerates concrete routes; content slugs must be listed explicitly. The `/zh` mirrors are generated by the SSG renderer's `expandRoutes` from `prefix_except_default`, not listed. A new top-level static page goes in `STATIC_ROUTES` there **and** in `src/constants/menus.ts`.
- **Post-build SEO is required**: ubean registers `/sitemap.xml` and `/robots.txt` as _runtime_ routes but excludes them from prerender output, so `build/seo.ts` writes both into `dist/public` after `ubean build`. Without it an SSG deploy 404s them. `DOCS_SITE_URL` sets the hostname.

## THE CONTENT-SLUG → ROUTE MAPPING

`src/shared/content-route.ts` is shared by the prerender collector, the site search index (`search-document.vue`, `api-search.ts`), the releases page, and the changelog helper — so a wrong slug produces a missing page **and** broken search hits and changelog links at once. The non-obvious rules:

| Content path (relative to `src/content/<locale>/`)  | Public route                                                  |
| --------------------------------------------------- | ------------------------------------------------------------- |
| `ui/components/<slug>`                              | `/components/<slug>`                                          |
| `ui/<slug>`                                         | `/overview/<slug>`                                            |
| `<section>/components/<slug>` (peripheral sections) | `/<section>/<slug>` — the `components` segment is **dropped** |
| `<section>/<slug>`                                  | `/<section>/<slug>`                                           |
| any trailing `index`                                | collapses to its directory root (`cli/index` → `/cli`)        |

## PLAYGROUND EXAMPLES

Examples live in `src/examples/ui/{component}/` (chart demos under `src/examples/chart/`) and are wired by `src/constants/globs.ts` via `import.meta.glob`, **not** by explicit imports. Naming is load-bearing:

- `NN-name.vue` — the `NN` prefix sets display order; two digits are required by the pattern. When both files carry a prefix the **lowest number wins**, so a `00-*` example is the first card and `01-basic` follows it.
- `basic.vue` is the **fallback** first card: the pin only decides when the prefix cannot (an unprefixed `basic.vue` beats every unprefixed file, and every prefixed file beats every unprefixed one). `UsageCode` resolves `<UsageCode component="…" />` by that `basic` **name**, so always keep a `basic` example.
- `index.vue` is **skipped**, and so is any file starting with `_`. Naming a demo `_wip.vue` therefore hides it from the site without deleting it.
- Files with no numeric prefix get `order: null` and sort after the prefixed ones, alphabetically.

`{component}/index.vue` is a thin `<PlaygroundGallery component="…" />` entry point; child demos must **not** carry their own title headings (the gallery supplies the title from locale keys under `playground.examples.<component>.<file>`).

## GENERATED DATA — NEVER HAND-EDIT

`src/generated/{api,api-locales,changelog,changelog-locales}/` and `public/{r,schema}/` are all produced by `pnpm sui gen …` and are inside the `sui check generated` drift set (see [packages/scripts/AGENTS.md](../../packages/scripts/AGENTS.md)).

Two consumers an agent might not expect:

- `public/r/` is the **vean registry** output, written by `packages/cli`'s `build:registry` step, which `apps/docs` `build` invokes first. So `pnpm build:docs` depends on the CLI package building.
- `src/generated/api/` is read at build time by `build/llms.ts` (not just rendered as Markdown) to emit LLM-facing docs summaries. Stale API JSON drifts the `/llms.txt` output too.

Markdown pages consume the data through host components: `<UsageCode component="…" />`, `<PlaygroundGallery … />`, `<ComponentApi … />`.

## BILINGUAL CONTRACT

`src/content/en` and `src/content/zh` must stay **structurally synced** — same files, same section order. This is enforced in two distinct ways, and only one of them is a hard gate:

- **Hard gate: changelog upgrade guides.** A `releaseChangelogNotes` entry with a `docPath` makes `sui gen changelog` **throw** unless `src/content/{locale}/<docPath>.md` exists for _every_ locale directory. So a breaking-change guide must land in en **and** zh in the same commit.
- **Note attribution is by release line.** `releaseChangelogNotes` keys name the release line (`v0.50.0` covers `v0.50.0-beta.1` … `v0.50.0`); the generator attaches the note to the **newest published release of that line**. So a note for an unreleased stable shows on the current prerelease, moves to the stable automatically, and the guide label (`UpgradeGuideEntry.version` / sidebar title) is the release line — never a beta build.
- **Convention: component pages.** Nothing fails if one locale is missing a component page; the site just shows an untranslated route. Treat the pairing as required anyway.

Non-English _generated_ copy is filled by `pnpm sui translate api` / `translate changelog` (needs `DEEPL_API_KEY`); do not hand-write into the `*-locales` JSON.
